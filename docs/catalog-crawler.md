# 谷库采集工作台

## 目标与边界

采集器用于把管理员明确授权的公开商品页面整理成待审核草稿。它不会直接发布 SKU，也不会携带登录 Cookie、执行网页 JavaScript，或绕过站点访问控制。

完整流程：

1. 管理员在 `/admin/crawler` 添加白名单入口。
2. 长驻应用每天北京时间 10:00、22:00 扫描启用来源，也可手动扫描。
3. 服务端解析商品结构化数据、下载并标准化允许域名中的图片。
4. 新内容按来源商品键去重后进入“采集草稿”。已发布或已拒绝的记录不会被重新打开来刷队列。
5. 管理员打开草稿，必须明确选择 IP / 系列，并可修改全部 SKU 字段、标签和图片。
6. “审核通过并发布到谷库”会在一个数据库事务里创建 SKU、标签、图片并把草稿标记为已发布。

只有 `admin` 可以维护来源、触发扫描、拒绝或发布草稿；`moderator` 无权操作采集器。三个采集表都启用 RLS 且没有客户端 policy，Supabase Data API 不能读取或写入它们。

## 可解析的页面

通用解析器优先读取：

- JSON-LD `Product`（支持数组、`@graph` 与 `ItemList`）
- 商品型 OpenGraph（仅在没有 JSON-LD Product 时回退）
- 同域、路径包含“详情路径特征”的普通链接

分类页如果使用 JavaScript 动态加载、没有结构化商品数据，或字段采用站点私有协议，运行记录会明确显示“需要专用适配器”。V1 不引入无头浏览器去猜测任意页面。

每个来源单次最多跟随 24 个详情页，每个草稿最多处理 4 张图片。额外图片 CDN 必须逐个加入该来源的“额外图片域名”；域名采用精确匹配，不支持模糊后缀。

## 图片标准化

采集图只接受 JPEG、PNG、WebP，源文件最大 10 MiB、解码像素上限 4000 万，并拒绝动画。处理步骤为：

- 应用 EXIF 方向后移除全部 EXIF / GPS 元数据
- 转换到 sRGB
- 商品主体等比放入 1344 × 1680 的安全区，小图不放大
- 居中裱到 1600 × 2000（4:5）浅色画布
- 导出质量 88 的 WebP
- 按输出字节 SHA-256 命名，重复图片只存一份

文件默认写入 `.data/catalog-assets`，通过 `/catalog-assets/<sha256>.webp` 提供不可变缓存。生产必须把 `CATALOG_ASSET_DIR` 指向持久磁盘；多实例部署则必须共享该目录或改接对象存储，否则不同实例看不到彼此生成的图片。

## 定时运行

自建长驻 Next.js 进程默认启用 `CATALOG_CRAWLER_SCHEDULER=1`。调度时刻固定为 Asia/Shanghai 10:00 与 22:00（UTC 02:00 / 14:00），数据库同时限制同一来源、同一时段只能生成一条运行记录，因此开发热更新或多实例不会重复入队。

如果部署形态不能保证长驻进程：

1. 设置 `CATALOG_CRAWLER_SCHEDULER=0`。
2. 在平台调度器中按北京时间每天 10:00、22:00 执行 `pnpm crawler:run`。
3. 保证任务使用与 Web 应用相同的 `DATABASE_URL`、`APP_URL`、`CATALOG_ASSET_DIR`。

应用停机期间不会凭空执行定时任务；需要由 systemd timer、容器平台或其他具备补跑能力的外部调度器保证时刻可靠性。

## 运维说明

- 白名单只解决技术授权边界，管理员仍须确认目标站点条款、robots 规则与图片使用权。
- 运行记录保留发现、入队、更新、跳过、失败数量和错误摘要。
- 发布后的新官图需要运行 `pnpm db:embed` 才能加入真实图像识别索引；在此之前 SKU 已正常进入谷库，但不会成为新的识别候选。
- 安全抓取逐跳校验协议、精确域名、DNS 公网地址、重定向、响应类型、超时与大小；不发送 Cookie 或认证头。
