# 网站设计快照画像

## 文档目的

这份文档不是工程说明书，而是给设计师的站点快照。

它回答 4 个问题：

1. 这个网站到底在服务什么产品目标
2. 用户会从哪些入口进入，最后落到哪里
3. 站内页面如何分层，哪些页面是主路径，哪些页面是支撑页
4. 优化全站使用路径时，应该优先改哪几段链路

---

## 一句话产品画像

这是一个以 `SKU` 为核心实体的二次元谷子图鉴网站。

它不是：

- 电商下单站
- 社交内容站
- 纯后台管理系统

它应该更像：

- 可检索的收藏图鉴
- 可沉淀收藏状态的个人收藏册
- 带轻社区与轻交换意向的 SKU 档案库

---

## 核心结构

### 1. 实体层级

全站的结构不是平铺的商品列表，而是四层图鉴关系：

- `IP`
- `Character`
- `Series`
- `Goods SKU`

其中真正承接用户动作的是 `SKU`：

- 收藏状态
- 评论
- 图片
- 评分
- 交换意向
- 识别确认结果

设计上要避免把重心放在“分类页本身很华丽”，却让 SKU 落点不够明确。

### 2. 用户动作层

V1 的真实动作只有几类：

- 搜索 SKU
- 浏览 IP / 角色 / 系列后进入 SKU
- 标记 `owned / wanted / exchange`
- 评论 / 晒图 / 评分
- 发布交换意向
- 通过识别进入候选，再确认到 SKU

也就是说，全站所有强交互都应尽量把用户送到 SKU 详情页完成。

### 3. 后台能力边界

前端可依赖的真实能力已经存在：

- 搜索和筛选
- SKU 详情数据读取
- 用户状态写入
- 评论 / 图片提交
- 评分提交
- 交换意向提交
- 识别候选接口
- 后台图鉴与商品管理
- 审核队列

因此设计时不需要再发明抽象概念页，重点是把这些已有能力串成更顺的路径。

## 站点地图

## A. 用户前台

### 首页

- 路径：`/`
- 作用：站点入口页
- 当前责任：
  - 提供搜索入口
  - 提供识别入口
  - 提供热门 IP 浏览入口
  - 提供精选 SKU 入口

### 搜索页

- 路径：`/search`
- 作用：全站最核心的发现页
- 当前责任：
  - 关键词搜索
  - IP / 角色 / 系列 / 类型 / 标签过滤
  - 列出 SKU 结果
  - 将用户送入正确的商品详情页

### SKU 详情页

- 路径：`/goods/[goodsSlug]`
- 作用：全站最重要的落点页
- 当前责任：
  - 展示图片
  - 展示结构化属性
  - 写入收藏状态
  - 承接评分 / 评论 / 图片 / 交换
  - 承接识别跳转结果

### IP 页

- 路径：`/ips/[ipSlug]`
- 作用：作品世界入口
- 当前责任：
  - 展示 IP 概览
  - 引导去角色页、系列页、SKU 列表

### 角色页

- 路径：`/ips/[ipSlug]/characters/[characterSlug]`
- 作用：角色维度聚合页
- 当前责任：
  - 角色信息
  - 角色相关 SKU 浏览
  - 角色补全感

### 系列页

- 路径：`/ips/[ipSlug]/series/[seriesSlug]`
- 作用：系列 / 活动批次聚合页
- 当前责任：
  - 系列信息
  - 该系列下 SKU 浏览

### 识别页

- 路径：`/recognition`
- 作用：从实物进入图鉴的入口
- 当前责任：
  - 调相机
  - 上传图片
  - 获取候选
  - 确认目标 SKU

### 登录页

- 路径：`/login`
- 作用：为收藏行为提供账户入口

### 我的收藏页

- 路径：`/me/collection`
- 作用：当前用户的收藏册
- 当前责任：
  - 已拥有
  - 想要
  - 可交换
  - 图片归档
  - 交换板
  - 收藏进度

### 他人收藏页

- 路径：`/users/[viewerKey]`
- 作用：公开收藏页 / Demo 收藏页
- 当前责任：
  - 展示他人的收藏结构
  - 展示其交换板与图片归档

## B. 管理后台

### 后台首页

- 路径：`/admin`
- 作用：后台总入口

### 图鉴管理

- 路径：`/admin/catalog`
- 作用：管理 IP / 角色 / 系列等图鉴实体

### 商品管理

- 路径：`/admin/goods`
- 作用：管理 SKU 条目

### 审核中心

- 路径：`/admin/moderation`
- 作用：审核评论、图片、交换意向和图鉴提案

## C. 系统与接口

- `POST /api/recognition/candidates`
- `/auth/callback`
- `/demo-assets/[...asset]`

这部分不是设计主舞台，但会影响关键流程体验。

## 页面模板归类

从设计系统角度看，这个网站其实只有 6 类页面模板：

### 1. 入口页

- 首页
- 登录页
- 识别页

特点：

- 决定“下一步去哪”
- 不应该承担太多解释

### 2. 结果页

- 搜索页

特点：

- 高密度信息
- 强过滤
- 快速扫读

### 3. 落点页

- SKU 详情页

特点：

- 图像、属性、动作三位一体
- 是最核心的转化页

### 4. 世界观聚合页

- IP 页
- 角色页
- 系列页

特点：

- 负责“浏览归属感”
- 但必须持续把用户往 SKU 推进

### 5. 个人沉淀页

- 我的收藏页
- 他人收藏页

特点：

- 不是功能页
- 是收藏成果展示页

### 6. 后台效率页

- admin 下所有页面

特点：

- 可以更工具化
- 但仍要保持层级清晰和高对比

## 主路径地图

## 路径 1：已知关键词进入

`首页 / 顶部导航 -> 搜索页 -> SKU 详情页 -> 收藏状态 -> 评论/评分/交换`

这是最重要的主路径。

设计优先级：`最高`

因为它最符合“我知道大概是什么，但要快速定位到具体 SKU”的真实使用场景。

## 路径 2：从作品世界进入

`首页 -> 热门 IP -> IP 页 -> 系列页 / 角色页 -> SKU -> 收藏动作`

这是“有作品归属感”的路径。

设计优先级：`高`

它决定网站有没有“同好归属感”，而不是只有工具感。

## 路径 3：从实物进入

`首页 / 独立入口 -> 识别页 -> 候选列表 -> SKU 详情页`

这是低信息起点路径。

设计优先级：`高`

它的本质不是“炫技识别”，而是“帮用户用最少认知成本进入正确的 SKU”。

## 路径 4：收藏沉淀路径

`SKU 详情页 -> owned / wanted / exchange -> 我的收藏页`

这是把一次浏览变成长期留存的路径。

设计优先级：`最高`

如果这条线不顺，网站就只是图鉴，不会成为收藏工具。

## 路径 5：后台维护路径

`后台首页 -> 图鉴 / 商品 / 审核`

这是内容维护路径。

设计优先级：`中`

它不决定用户第一印象，但决定全站内容质量是否可持续。

## 设计师应该重点理解的页面关系

### 1. 首页不是品牌长文页

首页的任务只有 3 个：

- 让用户立即搜索
- 让用户立即识别
- 让用户立即进入作品或 SKU 浏览

如果首页承担过多说明，它就会拖慢全站第一步。

### 2. 搜索页不是百科说明页

搜索页应该像“高质量目录检索器”：

- 输入清楚
- 过滤清楚
- 结果清楚
- 点击目标清楚

设计重点应放在扫读、过滤、结果排序感，而不是大段解释。

### 3. SKU 页不是内容广场

SKU 页要回答 4 个问题：

1. 这件东西是什么
2. 它属于哪个 IP / 角色 / 系列
3. 我能对它做什么
4. 其他人对它怎么看

如果它变成一个平权的信息杂糅页，用户会失去动作节奏。

### 4. 收藏页不是后台统计页

收藏页应该更像“收藏册 / 展示架 / 归档页”：

- 要有成果感
- 要有结构感
- 要有归属感

不能只是把 owned / wanted / exchange 变成三组列表。

### 5. 识别页不是技术炫耀页

识别页的价值不是算法本身，而是：

- 拍一下
- 看候选
- 认出来
- 进入 SKU

因此设计要减少对“流程说明”的依赖，强化取景、预览、候选确认三个节点。

## 当前信息架构判断

## 结构上已经成立的部分

- `SKU` 作为核心实体已经非常明确
- 路由层级基本清楚
- 前台和后台已分层
- 用户动作基本都能落到真实后端能力
- 搜索、识别、收藏、社区、交换已经形成完整闭环

## 设计上最值得继续优化的部分

### 1. 首页到搜索页

问题：

- 入口已存在，但还可以更果断
- 首页和搜索页之间的体验还不够像“同一条连续路径”

建议：

- 统一首页搜索框与搜索页检索区的视觉语言
- 强化“从首页直接进入搜索结果”的连续感

### 2. 搜索结果到 SKU 详情

问题：

- 搜索结果仍然偏“列表正确”，但“目标锁定感”还能更强

建议：

- 强化结果卡的主副信息层级
- 让“进入这件商品”成为非常明确的第一动作

### 3. SKU 详情页内部层级

问题：

- 已经比之前更克制，但主动作区、资料区、社区区的节奏还可以更紧

建议：

- 更明确地区分“先做动作”和“再看内容”
- 控制右侧信息块与下方社区块的视觉竞争

### 4. 收藏页的归属感

问题：

- 当前收藏页结构完整，但仍偏“分区内容集合”

建议：

- 更像个人收藏档案，而不是多个模块堆叠
- 需要更明确的个人风格容器、收藏成果焦点和展示秩序

### 5. 后台表格与编辑器

问题：

- 后台效率功能已经齐，但局部可读性和对比度需要持续巡检

建议：

- 后台统一表格高亮规范
- 后台统一表单分组层级

## 设计优化优先级建议

如果设计师要从“优化整个网站使用路径”出发，建议按这个顺序做：

### P0

- 首页
- 搜索页
- SKU 详情页

理由：

- 这是最高频主链路
- 也是最直接决定用户是否留下的链路

### P1

- 我的收藏页
- 他人收藏页
- 识别页

理由：

- 这部分决定归属感、留存感和低信息进入体验

### P2

- IP 页
- 角色页
- 系列页

理由：

- 它们决定浏览世界观是否成立
- 但不是第一优先级转化页

### P3

- 后台首页
- 图鉴管理
- 商品管理
- 审核中心

理由：

- 影响维护效率
- 不影响普通用户首条路径

## 给设计师的直接结论

这个网站不是“很多页面的集合”，而是 3 条体验骨架：

- `检索骨架`：首页 / 搜索 / SKU
- `归属骨架`：IP / 角色 / 系列 / SKU
- `沉淀骨架`：SKU / 收藏状态 / 收藏页

识别和后台都是支撑骨架：

- 识别负责把低信息用户送回主骨架
- 后台负责维持图鉴质量，让前台路径长期成立

所以设计优化不应该平均用力，而应该优先把以下 3 个关系做顺：

1. 首页如何更快把人送进搜索或识别
2. 搜索结果如何更快把人送进正确 SKU
3. SKU 如何更快把浏览变成收藏动作
