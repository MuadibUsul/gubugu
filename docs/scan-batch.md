# 连续扫描与正反面收藏

## 用户流程

- 手机扫描入口每批最多采集 10 件实物，一件一件放入取景区；不是同时检测桌面上的多件物品。
- 正面清晰稳定时沿用现有自动采集与裁切，也保留手动快门。已拍画面未明显变化时暂停自动采集。
- 每件正面必填，背面可跳过。点击「补拍背面」后翻面，背面只附加到选中的那件收藏，不另算数量。
- 点击「完成」匹配各件正面，在核对页删掉误拍、重拍单面、选择候选，然后明确确认保存。候选匹配不是鉴定保证；没有合适候选可以暂存为未鉴定。
- 私人谷柜的「实拍收藏」保留已归属和未鉴定照片，可以翻面查看，也可以为已有实拍收藏补拍或重拍背面。
- 未拍背面时显示标注「默认卡背」的品牌占位图，不能将占位图视为藏品的真实背面。

## 数据与安全

- 迁移 `0030` 仅为 `user_scans` 添加可空的 `back_asset_key`、`capture_id` 和用户/采集 ID 唯一索引，兼容旧记录。上线代码前必须迁移。
- 正反面经过同一私密图片规范化流程，分别限 10 MB、JPG/PNG/WebP；请求体另设流式总大小上限。
- 图片读取与补拍始终按登录用户检查所有权；背面读取使用原鉴权图片地址的 `?side=back`，不提供公开资产 URL。
- 每件实物单独事务保存，候选确认和私密记录写入同一事务。用户/采集 UUID 的事务锁与唯一索引保障并发重试不重复保存；部分失败只重试未确认成功的项。
- 若响应丢失，暂时锁定该项编辑，先用相同采集 ID 重试确认结果。已保存项不再重新提交。
- 用户实拍图不覆盖官方 SKU 图片；点亮沿用原 SKU 规则，不因补拍背面或重试增加数量。
- 仅正面进入现有识别服务，不新增付费 AI 或模型训练。

## 验证与边界

纯函数、上传边界、API 鉴权和预览无副作用测试进入 `pnpm test`。真实 PostgreSQL 测试在 CI 迁移、种子后单独运行：

```sh
RUN_DATABASE_TESTS=1 pnpm exec vitest run server/user-scans/save.integration.test.ts
```

该命令必须指向迁移完成的测试数据库，不要对生产库执行测试。数据库测试仅创建临时用户 ID 的记录，并清理自身数据。

当前批次照片保留在页面内存中，短暂断网可重试；刷新、关闭应用或离开页面可能丢失未保存照片，不承诺离线草稿恢复。画面去重属于轻量启发式判断，不是实物身份鉴定。真机仍需覆盖反光、透明保护套、相近卡背、弱光、相机权限和系统返回操作。
