# 图片无损保留与加载提速方案

状态：浏览加速已在本地实现并验证，尚未部署；现有大图未覆盖，上传前源文件的无损归档仍未实现。

## 本轮已实现

- 目录、社区、私密扫描共用 160 / 320 / 640 / 960 / 1280px 持久化预览；共享组件使用 srcset/sizes 自动选尺寸、屏外懒加载、首图高优先级。详情继续按需请求现有大图，背面低优先级。
- 预览保存在资产目录的 `.previews-v1` 内，原文件不修改；上传时预热 160/320，其余尺寸首次访问生成并复用磁盘缓存。单进程串行转码、最多排队 16 个尺寸，拥塞/失败临时回退原图且不缓存回退响应。
- 私密图和可撤销的社区图均先鉴权再检查 ETag，使用 `private, no-cache`；公开哈希目录图 immutable。Service Worker 不缓存私密/可撤销图片，并清理旧版缓存。
- 缩略图使用现有 WebP quality 90，不宣称数学无损；编码后比源文件大时使用源文件内容。12 张本地已有目录图实测：原文件合计 1,304,606 bytes，320px quality 90 合计 389,130 bytes（约减少 70%）；同批无损缩略图 1,814,882 bytes（反而增加 39%）。这是本地样本，不是全站速度承诺。
- 不优化外部图床、blob 临时拍摄预览或占位 SVG；不新增付费服务、数据库缓存或全局状态框架。

## 上线与旧图预热

发布前在有 pnpm/tsx 的环境顺序预热明确指定的资产目录（生产路径以部署配置为准）：

```sh
pnpm exec tsx --conditions=react-server scripts/warm-image-previews.ts .data/catalog-assets .data/user-scans .data/community-images
```

脚本可重复运行、不覆盖原文件，仅处理哈希命名的 WebP，不递归扫描其他目录。生产运行镜像可能没有 tsx，应使用维护/构建环境挂载对应资产卷。不预热也能兼容旧图，但首次访问有转码开销。部署前检查磁盘余量；派生目录占用额外空间，可随资产卷备份，源文件删除后残留预览不会由鉴权接口提供。整个站点的网络耗时、后端查询、Android 冷热启动仍需线上弱网测量。

## 已确认的问题

- 实拍列表的缩略图与详情使用同一个图片 URL，小卡片也下载完整图像。
- 私密扫描图片响应为 `private, no-store`；这是隐私优先的设置，但不能利用持久 HTTP 缓存重复读取。
- 现有入库流程缩至长边 1400px，并使用 WebP quality 90，不能称为无损归档。
- 不能通过转码恢复旧图已经丢失的细节；本轮不重新压缩现有收藏。

## 本地样本实测

使用现有 Sharp 0.33.5，在内存中处理 3 张本地 PNG 样图，不覆盖任何文件。它们不是线上用户照片，结果不能当成全站节省率。

| 样本               | 原文件 bytes | 原尺寸无损 WebP bytes | 320px 展示缩略图 bytes |
| ------------------ | -----------: | --------------------: | ---------------------: |
| guzi-sample-01.png |      2736448 |               1928962 |                 104930 |
| guzi-sample-02.png |      2697979 |               1950900 |                 107730 |
| guzi-sample-03.png |      2528343 |               1834544 |                 105768 |

原尺寸无损编码只节省约 27–30%；缩略图节省约 96%，但它经过缩放，**不是原图的数学无损版本**。JPEG/已压缩 WebP 转无损格式也可能变大。

## 建议实施顺序

1. **先减少重复传输，不降画质。** 私密图仍逐次验证身份和所有权，验证完成后才处理 ETag / If-None-Match；响应采用 `private, no-cache`，不变返回 304。验证退出、切换账号、删除照片和补拍背面时不会错用缓存。禁止放到公共 CDN 或共享 Service Worker 图片缓存中。公开哈希目录图继续使用现有 immutable 缓存。
2. **分离展示尺寸与归档图。** 新图片入库时一次性生成 320px / 640px / 清晰大图，列表根据显示宽度与 DPR 使用 srcset/sizes；详情按需加载大图，背面在正面可见后低优先级预加载。不是每次 GET 都现场转码。旧图分批生成派生图，不覆盖现有文件。
3. **提供真正的源图保留。** 对新上传内容单独保留受鉴权保护的源文件，明确定位元数据的隐私处理。无损 WebP 是可选的归档编码，对比原文件大小与解码像素后再决定；较大则保留源格式。原图与派生展示图分开存储，避免重复有损转码。旧图片无法凭空恢复为上传前的原始文件。

## 验收

- 比较代表性卡面：细字、线稿、深色、镭射反光、透明 PNG 和实拍照片。
- 无损版本比较解码像素，不用“肉眼差不多”冒充无损。
- 测量冷/热缓存、首张卡可见时间、请求数、传输字节与移动端解码耗时，不预先承诺秒开。
- 现有 VPS CPU 较弱，先沿用 Sharp，不引入新的付费服务或在线重编码负担。
