谷布谷 移动端

收藏身份优先：谷柜主页 + Feed 是主场，相机点亮是最短路径的入口，换谷是关系的兑现。以下是我开工前的假设与设计系统，先过一遍再往下画。

1 · 已确认的输入

导航

4 Tab：首页 / 换谷 / 消息 / 我的。相机放在首页头部主入口，不占 Tab。

主张

收藏身份与社交炫耀 —— 谷柜是可分享的资产页。

语气

圈内口语：谷友、蹲谷、点亮、开柜、换谷。

形态

Android 边框，静态高保真 + 关键流程可点击。

2 · 我的假设（请纠正）

  1. 视觉语言用 Nocturne，不沿用仓库现有的暖红/金「典藏图鉴」皮。结构、交互与文案沿用仓库真实实现；只换色板与字体。若要保留原皮，说一声我改。
  2. 「点亮」是唯一计入进度的动作：owned + lit_at。手动标记「已拥有」只入柜、不点亮，UI 必须能一眼分清（实心 / 描边）。
  3. 谷库无限下滑流：搜索页与图鉴页都是瀑布/网格无限流，筛选收进吸顶胶囊条，不做分页。
  4. 状态模型三选多：已拥有 / 想要 / 可交换 可同时成立，详情页做三态并列而非单选。
  5. 换谷永不涉现金，报价界面里没有金额字段，只有物换物与最多三次反提计数。
  6. 识别结果必须人工确认，UI 不暗示自动准确；置信度用分数 + 中文档位（高度接近 / 较高可能 / 可作为候选 / 信号偏弱）。

3 · 屏幕清单（12 流程）

首页 IA 谷库无限流 + 筛选 SKU 详情 谷柜 / 完成度 相机取景 → 候选 → 点亮 换谷匹配卡 / 报价协商 换谷广场发帖 Feed / 关注 私信会话 成就 / 角色收藏圈 / 排行 通知中心 登录注册 分享谷卡

实心标签 = 会给多方案对比（谷柜可视化形态、识别确认交互、换谷卡片与报价流程、首页信息架构），其余各一版。
